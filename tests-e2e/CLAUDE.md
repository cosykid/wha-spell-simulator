# tests-e2e/

Playwright specs that drive the real simulator in Chromium: draw strokes, seal the ring, assert the wired-up UI.

## How to run

```sh
npm run test:e2e                  # playwright install && playwright test
npx playwright test fire-shoot    # one spec
npx playwright test --ui
```

Locally the config starts `npm run dev` on 5173 and reuses an already-running server. CI builds and serves `npm run preview` on 4173.

**Never run the suite from a git worktree while a dev server is up on 5173.** `reuseExistingServer` makes the worktree's run silently exercise the main checkout's code — screenshots and golden baselines then pin the wrong tree. From a worktree, point a throwaway config at a free port instead.

## Map

- [`pages/SpellCanvasPage.ts`](pages/SpellCanvasPage.ts) — the page object. Every canvas interaction goes through it.
- [`fire-shoot.e2e.ts`](fire-shoot.e2e.ts) — the reference cast: prepared, sealed, active, then the beats read off the effect canvas, plus a seal-to-active latency benchmark. It proves the production wiring; whether the fire _looks_ right is the look tier's job.
- [`classic-shoot.e2e.ts`](classic-shoot.e2e.ts) — the same cast under the classic style, plus the toggle. Separate from `fire-shoot` on purpose: classic holds every particle back through the portal tilt where the stage fills it with R-01's ambient medium, so `fire-shoot`'s first beat assertion inverts and a shared spec could assert nothing about either.
- [`eraser.e2e.ts`](eraser.e2e.ts) — erase splits a stroke and undo restores it, read from glyph-canvas pixels.
- [`spent-page.e2e.ts`](spent-page.e2e.ts) — the exits out of a spent one-shot: the tap that tears the page off, the status note's fresh-page button, and its reopen button, which hands the sealing stroke back so the diagram can be edited and sealed again.
- [`shape-placement.e2e.ts`](shape-placement.e2e.ts) — palette drag-to-place, arrange mode, ring z-order, copy and paste.
- [`library.e2e.ts`](library.e2e.ts), [`spell-presets.e2e.ts`](spell-presets.e2e.ts) — database backed, skipped by default.
- [`golden-look.e2e.ts`](golden-look.e2e.ts) — the look golden tier: the Spell Effect Lab's effect canvas per lab preset at fixed timestamps, plus the discriminative floor that compares the baselines to each other. A case with no baseline skips.
- [`helpers/strokes.ts`](helpers/strokes.ts) `circleStroke`, [`helpers/castProbe.ts`](helpers/castProbe.ts) the in-page half of reading a cast, [`helpers/account.ts`](helpers/account.ts) auth and drawer helpers, [`helpers/types.d.ts`](helpers/types.d.ts) `NormPoint` / `NormStroke` / `RingGeometry`, [`fixtures/sampleSpells.ts`](fixtures/sampleSpells.ts) `FIRE_SHOOT`.

## Invariants and gotchas

- **Go through `SpellCanvasPage`.** `goto`, `waitForReady`, `drawStroke`, `drawOpenRing`, `sealRing`, `castSpell`, `armCastClock`, `measureActivation`, `sampleCast`, `waitForCastEnd`, `expectActive` are the vocabulary. Add new interactions to the page object, not inline in a spec.
- **Wait on `data-input-ready`, not on status text.** `waitForReady()` does this. The status leaves "Loading" before drawing capture attaches its pointer listeners, so a stroke drawn on status alone is silently dropped.
- **Seal last.** `castSpell` draws the open ring, then the symbols, then the closing arc. Closing the ring sets `canvasLocked` and every later freehand stroke is ignored — until the cast is spent, when the next primary tap tears the page off instead and the status note offers that tear beside a reopen that hands the sealing stroke back (`spent-page.e2e.ts`). Pass `skipSeal: true` to stop at prepared.
- **Coordinates are normalized 0..1 over the canvas box**, then inset toward the center by `drawScale` (0.85). The 1024x1024 square viewport exists so the cover-square canvas fills the window exactly and those coordinates map 1:1. Do not change the viewport, it moves every stroke.
- **Drive input with `page.mouse`**, the way `drawStroke` does. Real pointer events flow through drawing capture, and it already emits down, moves, up, plus a settle delay.
- **Let the paper come back down before drawing on it.** The portal tilt is a 980ms CSS transition and a stroke is mapped through the canvas box as it stands, so a stroke drawn while a spell is still untilting lands where nothing aimed, or misses the element entirely and never reaches capture at all. Any spec that draws just after a cast ends calls `waitForPaperSettled()` first. The symptom when it does not is a status that never leaves `Prepared spell`.
- **Recognition is async and debounced.** Each `drawStroke` waits `settleMs` (default 90). Raise it for a slow machine rather than sprinkling bare `waitForTimeout` into a spec.
- **Assert on the settled status.** The values are `Loading`, `No ring detected`, `Prepared spell`, `Active spell`, plus the `Ring closed - ...` family for a sealed ring with no usable sigil. That family also shows transiently while the ML pass refines a template result, so never assert on the first status you see after sealing. `expectActive()` waits on both the text and `data-status-class="active"`.
- **A cast is a one-shot with beats, and the clock starts at activation.** R-01: `charge` spans the 980ms portal tilt and carries the ambient medium alone, `strike` is the next 320ms and brings the spell itself, `body` is elastic, then `release` and `afterglow` fade it out; past `totalMs` the effect canvas is empty. Read the beats through `sampleCast` and `waitForCastEnd` on the page object, which measure from the clock `armCastClock`/`measureActivation` stamps. Sample a whole beat sequence inside **one** `page.evaluate` pass, the way `sampleCast` does — a round trip between two samples can step the cast past a beat boundary.
- **`reducedMotion: 'reduce'` is deliberate.** Drawer and panel slide transitions are guarded by it. Without it a drag reads a palette card's box mid-animation and lands off the moving card.
- **`fullyParallel: false` and `workers: 1` are deliberate, together.** Casts contend for the recognition worker pool and the GPU, and `fullyParallel: false` alone still ran separate files in parallel workers — a handful of concurrent WebGL casts starved each other into 90s timeouts on trivial calls. The specs sum to ~7 minutes, so the serial suite is not slower than the contended one was; it is also what retired the recurring `cast-none` golden-look timeout. Retries are 1 locally and 2 on CI to absorb timing flake.
- **Escape closes drawers** (`closeDrawer`). The open drawer covers the tab rail, so clicking the tab a second time does nothing.
- **Two different spell cards.** `spell-card` is a My Spells drawer row, `library-spell-card` is a library plate. Filter by name as well as by test id.
- **The look tier is two lists, because there are two styles and they do not share a clock.** The stage list (`cast-*`, 63 baselines) is every lab preset at 700/1150/2200ms, read off R-01's beat clock: 700ms is charge _content_ (the seal's ink igniting and the ambient medium, with the spell's own manifestation still to come), 1150ms is inside the strike, 2200ms is mid-body of a 5s cast. Two more cases run `column-balanced` under the `crystal` and `aeroform` sigils, so the only difference between those baselines and the plain one is the look row.
- **The classic list (`classic-*`, 33 baselines) runs at 300/1400/2600ms on the wall clock**, because classic holds all emission back until the 980ms portal tilt is over: 300ms is mid-tilt and empty _by contract_, 1400ms is just after emission opens, 2600ms is the effect developed. It is a deliberate subset rather than every preset, because classic is frozen behavior and per-preset coverage buys less there. Three presets cover its field renderer and eight sigils over the sign-free `none` preset cover its five element renderers and three sigil variants — classic picks the field renderer for any seal with force sources, so a sigil variant only shows on a seal without them. Its tolerance is 0.02 against the stage's 0.005, and `Math.random` is seeded in the page for classic cases only; the stage draws from its own seeded `Rng` and must not have its baselines moved by something the app never does.
- **A classic baseline is only reproducible because the page renders once.** The seeded `Math.random` is one stream, so a second pass over the same frame consumes different values and paints different pixels. The lab builds its preview in an `untrack`ed `$effect` for exactly this reason: tracked, the golden path's synchronous render subscribed the effect to the `activatedAt` it had just written, and the page re-rendered until Svelte's depth guard stopped it. If classic baselines ever start drifting run to run, look for a second render before you look at the engine.
- **The discriminative floor is stage-only.** `distinct presets render distinctly` compares `cast-*` baselines to each other. Comparing across styles would be meaningless, and classic is not where a tuning pass narrows the field.
- **Look baselines live in `golden-look.e2e.ts-snapshots/`.** Regenerate with `npm run test:golden:look:update` after any deliberate visual change, and eyeball the diff before committing. If a baseline is missing its case skips with a hint instead of failing. The 0.5% pixel tolerance only absorbs Chromium's dithering: the cast engine is seeded end to end and reads no clock, so nothing else should move. Note that the lab synthesizes its own `SpellIR.signature`, which the score seeds from, so a change to how that signature is composed reseeds every cell and rewrites all 63 baselines even when no behaviour moved; prove that case against the cast tier, which pins its own signature. The primary gate is that tier (`npm run test:golden`, see [`../tests/CLAUDE.md`](../tests/CLAUDE.md)); this one only catches what pixels can say and motion cannot.
- **A baseline matching itself proves nothing on its own.** Phase 5's goldens all passed while five spells rendered identically, so the tier also asserts that _distinct presets differ from each other_ at the 2200ms frame by more than a floor. Presets whose plan has nothing to steer (`none`, `swirl-pushes`, `column-cancelled`) are exempt from each other and from nobody else — they are meant to render R-11's one designed default. If a tuning pass ever narrows the field, this is the test that says so.
- **The effect canvas is WebGL under the stage, so reading pixels back takes asking.** A drawing buffer is discarded at composite unless the page requested otherwise, and `getContext('2d')` on that canvas returns null. `SpellCanvasPage.goto` therefore loads `/?castReadback=1` ([`../src/lib/cast/stage/readback.ts`](../src/lib/cast/stage/readback.ts)), which is the only thing the page under test asks the app for that production does not; the look tier's scripted clock turns the same flag on for itself. `helpers/castProbe.ts` then reads the stage's own context with `readPixels`. Under classic the canvas is 2D, the flag is a no-op, and the reader is `getImageData` at a threshold of 8 rather than 32 — `getImageData` is not premultiplied and classic lays no ambient haze over the plane for the threshold to have to see past.
- **The probe is told which reader to use and never finds out.** Asking a canvas for a context it does not have _creates_ one, and a canvas that has handed out a `2d` context can never return WebGL, so a `try webgl, else 2d` probe would permanently poison the canvas for whichever style loaded second. `castProbe` branches on the `data-effect-style` the host stamps on the element, and rebinds when a style switch mounts a fresh one.
- **A look frame is driven, never waited on.** `?preset=<id>&frameMs=<n>` on `/tools/spell-effect-lab` loads a preset and steps the preview to that timestamp on a scripted clock, then stops and stamps `data-golden-frame` on the effect canvas. **The clock is walked at sixty frames a second, never jumped**, for both engines: a baseline is a picture of a frame a display could show, and both carry state a frame builds on — classic steps a particle system per call, the stage advects a seeded tracer population per step and its pixels are a pure function of that state. A stage baseline costs a few seconds because of it. `&sigil=<id>` picks the look row, narrowed against the lab's own sigil list so a URL cannot select one that does not exist. The hook is test-only and lives in [`../src/routes/tools/spell-effect-lab/lab-goldens.ts`](../src/routes/tools/spell-effect-lab/lab-goldens.ts).
- **Database specs are opt-in and destructive.** `library` and `spell-presets` call `test.skip(DB_SPECS_DISABLED, ...)` unless `E2E_DB=1`, because they register accounts and write spells. A local `.env` may point `DATABASE_URL_VPS` at the production database. Start the throwaway Postgres first (`docker compose -f docker-compose.dev.yml up -d`, then `npm run db:migrate`) and repoint `DATABASE_URL_VPS` at it before enabling.

## Writing a new spec

1. Name it `<subject>.e2e.ts`. `testMatch` is `**/*.e2e.{ts,js}`, so a `.test.ts` here never runs.
2. Open with `const canvas = new SpellCanvasPage(page); await canvas.goto();`.
3. To cast, replay a fixture: `castSpell(FIRE_SHOOT, { skipSeal: true })`, assert `Prepared spell`, then `sealRing(DEFAULT_RING)` and `expectActive()`.
4. To build a diagram without hand-drawing it, open the Shapes panel and drag `#shapesRootPanel .shape-card .reference-preview` onto the canvas (see `shape-placement.e2e.ts`). A dropped ring lands prepared with a 45 degree gap at the palette's own radius, not `DEFAULT_RING`'s, so seal it against its own geometry.
5. Prefer `getByTestId`. When a control has no test id, add a `data-testid` to the component instead of reaching for a CSS selector.
6. For a database spec, guard it with `test.skip(DB_SPECS_DISABLED, DB_SPECS_REASON)` and reuse `uniqueUsername`, `registerViaMySpells`, `saveCurrentSpell`.
